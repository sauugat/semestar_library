1. EXECUTIVE SUMMARY & PURPOSE
================================================================================
Semester Library is an all-in-one academic and developer platform created 
specifically for Gandaki University students (primarily Bachelor of Information 
Technology - BIT). 

It centralizes curriculum syllabus breakdowns, semester-wise lecture notes, 
PowerPoint slides, official exam routines, campus notices, an interactive 
programming playground ("Code Lab") with an online compiler and assignment 
grading system, real-time peer group chat, and an AI-powered academic assistant 
("Semester AI") that can search through uploaded lecture documents.

2. COMPLETE TECHNOLOGY STACK
================================================================================

A. RUNTIME & BACKEND
--------------------------------------------------------------------------------
- Environment: Node.js (>= 22.13.0)
- Backend Framework: Express.js (v4.19.2)
- Session Handling: express-session (v1.18.0)
- Session Persistence: connect-pg-simple (v10.0.0) - stores sessions directly
  inside PostgreSQL so login state persists across serverless instances
- Password Hashing: bcryptjs (v2.4.3) - salted password hashing
- File Uploads: Multer (v1.4.5-lts.2) - multipart/form-data upload handling
- Rate Limiting: express-rate-limit (v8.7.0) - protects auth and AI endpoints
- WebSockets: ws (v8.21.3) - bidirectional live terminal runner and streaming
- Hosting & Infrastructure: Vercel Serverless Functions via api/index.js 
  and vercel.json rewrites

B. DATABASE & STORAGE LAYER (DUAL-ENGINE SYSTEM)
--------------------------------------------------------------------------------
- Dual Database Architecture (db.js):
  1. Primary Production Database:
     Neon Database (Serverless PostgreSQL)
     Driver: @neondatabase/serverless with pg pool over WebSockets.
  2. Fallback / Development Database:
     Turso Database / LibSQL (@libsql/client) or local SQLite (database.db).
  3. Dynamic Query Translation:
     Automated SQL parameter conversion from SQLite '?' to Postgres '$1, $2, ...'.
- Object & File Storage:
  Supabase Cloud Storage bucket ('library_files' & 'posts') with fallback 
  to local /uploads/ directory.
- Real-Time Messaging Engine:
  Supabase Realtime Broadcast Channels ('public:chat_messages').

C. FRONTEND & CLIENT-SIDE ARCHITECTURE
--------------------------------------------------------------------------------
- Languages: Vanilla Semantic HTML5, Modern CSS3 with CSS Variables, ES6+ JavaScript.
- Design Aesthetics:
  - Dark-mode first design inspired by Apple, Linear, and Vercel.
  - Neutral monochrome palette (#0a0a0a, #171717, #242424).
  - Smooth glassmorphism (backdrop-filter: blur(16px)), subtle borders, 
    magnetic buttons, and bento grid layout.
- Theme Engine (theme.js & theme-overrides.css):
  - Instant anti-FOUC (Flash of Unstyled Content) execution in <head>.
  - Dark / Light mode switching with localStorage persistence.
- Typography (Google Fonts):
  - Plus Jakarta Sans, Outfit (Headings & Brand)
  - Inter (Body and UI text)
  - Fira Code, JetBrains Mono (Code editors, terminal output, snippets)
- Progressive Web App (PWA):
  - Service Worker (sw.js) for background caching and offline reliability.
  - Web App Manifest (manifest.json) for desktop and mobile home-screen install.
  - Apple touch icons and mobile web app capability headers.

D. INTEGRATED CLIENT & PARSING LIBRARIES
--------------------------------------------------------------------------------
- Monaco Editor (vs/loader.js): Full VS Code browser code editor with syntax

- PDF.js (pdfjs-dist 6.3.289): In-browser canvas rendering for PDF note previews.

5. AI ASSISTANT ("SEMESTER AI") ARCHITECTURE & RETRIEVAL
================================================================================
Semester AI is engineered specifically for academic accuracy and zero hallucinations:

A. Core Models
- Primary: gemini-3.1-flash-lite (fast, low latency, high token capacity).
- Complex Queries: gemini-3.1-pro-preview (advanced reasoning).
- Provider Fallback: OpenRouter REST API contract without bloated SDK dependencies.

B. Grounded Autonomous Tool Calling (lib/chat-tools.js)
The model has access to 4 specialized backend tools:
1. search_notes: Searches indexed full-text lecture notes and PDF contents.
2. get_syllabus: Queries official course unit contents from syllabus-data.json.
3. get_routine: Queries examination schedules and dates.
4. web_search: Fetches live external documentation or recent tech developments.

C. Full-Text Document Ingestion Engine (lib/note-search.js)
When notes are uploaded:
- PDF files are read via pdfjs-dist.
- Word documents are parsed via mammoth.
- Presentations are extracted via node-pptx-parser.
- Text is normalized and indexed into note_search_documents table:
  - In PostgreSQL: Stored as TSVECTOR with GIN Index (to_tsvector('english', content)).
  - In SQLite: Stored in an FTS5 virtual table (tokenize='porter unicode61').

6. DATABASE SCHEMAS & DATA MODELS
================================================================================

- students:
  id, student_id (unique roll), name, email, password_hash, semester,
  avatar_url, bio, role ('student', 'admin', 'instructor'), created_at.

- files:
  id, student_id, original_name, stored_name, subject, semester, chapter,
  file_type, file_size, download_count, created_at.

- note_search_documents:
  id (FK -> files.id ON DELETE CASCADE), content, extraction_status,
  extraction_error, indexed_at, content_truncated, search_vector (TSVECTOR).

- posts:
  id, student_id, post_type ('text', 'resource', 'assignment'), content,
  attachment_url, attachment_type, likes_count, comments_count, created_at.

- post_likes:
  id, post_id, student_id, created_at (UNIQUE on post_id + student_id).

- post_comments:
  id, post_id, student_id, content, created_at.

- chat_messages:
  id, student_id, message, attachment_url, attachment_type, created_at.

- code_lab_assignments:
  id, title, subject, language, description, starter_code, test_cases (JSON),
  due_date, created_by, created_at.

- code_lab_submissions:
  id, assignment_id, student_id, code, language, status ('passed', 'failed'),
  score, test_results (JSON), execution_time, created_at.

- notifications:
  id, recipient_id, actor_id, type, title, message, link, is_read, created_at.

- followers:
  id, follower_id, following_id, created_at (UNIQUE constraint).

- session (PostgreSQL connect-pg-simple):
  sid, sess (JSON), expire.
